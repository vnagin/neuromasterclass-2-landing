День 4

Агент оживает

Подключите реальный триггер и действие и соберёте сквозной авто-прогон end-to-end.

⏱ 40–60 мин · Уровень: начинающий
🎯 Цель дня

Убрать ручной запуск — агент должен сам реагировать на событие и сам выполнять действие. Полный авто-прогон от триггера до уведомления.

📖 Теория

Триггеры: на что агент реагирует

До сих пор мы запускали агента вручную (Manual Trigger). Теперь подключаем реальный источник событий. На выбор в n8n:

  • Webhook — универсальный приёмник. Любая система (сайт, CRM, форма) отправляет POST-запрос на URL агента — и он срабатывает.
  • Gmail Trigger — новое письмо в ящике. Агент читает тему, тело, отправителя.
  • Telegram Trigger — новое сообщение в боте/канале.
  • Google Sheets Trigger — новая строка в таблице.

Для анкерного кейса используем Webhook — как будто заявка прилетает с сайта.

Действия: что агент делает на выходе

После того как LLM вернул JSON, нужно с ним что-то сделать:

  1. Запись результата — сохранить поля в таблицу (Google Sheets / n8n Data Table). Чтобы потом анализировать все заявки.
  2. Уведомление владельцу — отправить черновик ответа менеджеру (email / Telegram).

Как связать выход LLM (JSON) с полями действия

После LLM-ноды добавьте ноду «Code» / «Set» для парсинга JSON. В n8n данные из LLM приходят в поле {{ $json.message.content }} — это текст JSON. Код на JavaScript парсит его, и поля становятся доступны как {{ $json.category }}, {{ $json.draft_reply }} и т.д.

[SCREENCAST D4 из LEA-2448: подключение Webhook-триггера, нода Code для парсинга JSON, Append Row в Google Sheets, уведомление в Telegram]
🛠 Практическое задание

  1. Замените Manual Trigger на Webhook. Удалите старый триггер, добавьте «Webhook» → «Test URL» → скопируйте Production URL.

  2. Добавьте ноду «Code» после LLM для парсинга JSON-ответа. Код:

    const llmOutput = $input.first().json.message.content; const parsed = typeof llmOutput === 'string' ? JSON.parse(llmOutput) : llmOutput; return { category: parsed.category, priority: parsed.priority, client_name: parsed.client_name, summary: parsed.summary, draft_reply: parsed.draft_reply };

  3. Добавьте действие 1 — запись в таблицу. Нода «Google Sheets» → «Append Row» (или «n8n Data Table»). Подставьте поля из JSON: {{ $json.category }}, {{ $json.client_name }} и т.д.

  4. Добавьте действие 2 — уведомление. Нода «Telegram» / «Email». Отправьте себе сообщение с полями заявки и черновиком ответа.

  5. Прогоните end-to-end. Отправьте тестовый POST-запрос на Webhook URL (через Postman / curl) и проверьте, что данные записались в таблицу и уведомление пришло.

⚡ Express-дорожка: импорт готового шаблона

Нет времени собирать с нуля? Импортируйте готовый стартовый workflow:

Скачать agent-starter-workflow.json

В n8n: «Import from File» → выберите скачанный JSON. Все ноды уже собраны под анкерный кейс. Останется только подставить ваш API-ключ LLM, промпт и credentials для Google Sheets/Telegram.

⚠️ Trade-off: быстрее результат, но меньше навыка ручной сборки. Рекомендуем пройти путь «с нуля» хотя бы раз.

✅ Чек-поинт

Само-проверка Дня 4

  • ✅ Webhook-триггер подключён (Manual Trigger заменён)
  • ✅ JSON парсится и поля раскладываются по переменным
  • ✅ Данные записываются в таблицу (Google Sheets / n8n Data Table)
  • ✅ Уведомление (email / Telegram) отправляется с черновиком ответа
  • ✅ Полный авто-прогон: тестовый POST → запись + уведомление — без ручного запуска
Рубрика «выполнено хорошо»: полный авто-прогон с записью в таблицу и уведомлением. Все поля (category, priority, client_name, summary, draft_reply) корректно записаны.
🔀 Адаптировать под себя

Новичок: собирайте анкерный кейс как есть. Webhook + Google Sheets + Telegram.

Своя задача: триггер и действия под вашу задачу — возможно, вам нужен Gmail Trigger или запись в другую систему (Airtable, Notion, CRM). Схема та же: триггер → LLM → парсинг JSON → действия.

Express: импортируйте agent-starter-workflow.json и заполните только свои ключи и промпт.
